    scripts/monitor 脚本功能说明¶

    目录按功能分为三组：顶层入口（cron/make 直接调用）、core/（运行主链）、login/（登录与恢复）。 全部脚本自 2026-11-09 起随 trae-cli 2.x 适配。

    目录结构¶

    scripts/monitor/
├── preflight.sh        # 顶层入口：交易日预检（六项）
├── force_cleanup.sh    # 顶层入口：兜底回收（15:20 cron）
├── deploy.sh           # 顶层入口：首次部署
├── core/               # 运行主链（生产在用）
│   ├── monitor_poll.py     # 盘中轮询 + LLM 分类推送（当前生产主程序）
│   └── runtime_state.py    # 状态管理基础件（state/heartbeat/pid/游标/推送统计）
├── login/              # 登录与恢复
│   ├── captcha_solver.py     # 滑块缺口识别 + 拟人轨迹（ddddocr，独立 venv）
│   ├── verify_auth.py        # Cookie 续期五项验证清单
│   ├── auth_input_code.sh    # 辅助登录验证码回传（make auth-input-code）
│   ├── auth_local_login.sh   # 本地有头登录（Cookie SOP 路径 A，本地电脑用）
│   ├── auth_vnc.sh           # noVNC 应急续期（Cookie SOP 路径 B）
│   └── profile_pack.sh       # 浏览器 profile 打包（SOP 路径 A 的上传件）
└── .venv/              # 仅 ddddocr（git 忽略，换目录需重建）

    各脚本功能详述¶

    顶层入口（cron / make 直接调用）¶

    脚本 功能 触发方式
    preflight.sh 交易日预检六项：①PAT 认证探活（traecli models）②浏览器 profile 含 Cookie ③直播站连通 ④磁盘 >500MB ⑤交易日判断（API 异常按工作日放行）⑥凭据完整性（项目根 .env 的手机号与 webhook；兼容 memory.md 旧方式并告警提示迁移）。任一不过即告警退出、不启动监控 cron 08:45 / make preflight
    force_cleanup.sh 兜底回收：杀残留 traecli 盯盘会话、看门狗、占用 profile 的 Chromium cron 15:20 / make monitor-stop
    deploy.sh 首次部署：系统依赖 → traecli → Playwright → ddddocr venv → runtime 目录结构 make deploy

    core/（运行主链）¶

    monitor_poll.py —— 当前生产主程序（2026-11-09 上线的轮询 + LLM 编辑架构）：

    • 60 秒/轮：滚动到消息区底部 → 提取最近 40 条 .pointList.msglay → 增量识别（index 游标 + MD5 内容哈希双去重，防 MQTT 补发重推）；
    • 老师新消息（李朋/廖峥开头）→ 触发一次独立 traecli exec 编辑任务：按 7 类分类 → 达标内容调 send_webhook 推飞书卡片 → 碎片跳过；编辑失败自动重试一次，仍败记日志留待补推（不降级转发）；
    • 每轮 touch runtime/heartbeat、游标写 runtime/state.json；
    • 自愈：连续 12 轮无新消息刷新页面（MQTT 断连）；连续 3 轮异常重建整个浏览器 context（修自 11-09 上午崩溃 5 小时事故）；
    • 必须以 xvfb-run 有头模式运行（无头被易盾拦截）。

    runtime_state.py —— 状态管理基础件（被 verify_auth/Makefile 引用）： RuntimeState 类：state.json 读写（auth_status、msg_cursor_total、stats）、heartbeat、monitor.pid、推送计数、内容哈希。

    login/（登录与恢复）¶

    脚本 功能
    captcha_solver.py 易盾滑块自动识别：ddddocr slide_match() 本地识别缺口 x 坐标 + 拟人轨迹生成（正弦变速/垂直微抖/过冲回拉）。子命令：gap（只识别）、track（只生成轨迹）、solve（完整：返回 gap_x + 轨迹）。make captcha-test 离线回归
    verify_auth.py Cookie 续期后的五项验证：URL 为 vips.html、无登录表单、消息容器非空、auth_status 置回 valid、续期历史落盘（make auth-verify）
    auth_input_code.sh 辅助登录验证码回传：把 6 位码写入 runtime/sms_code.txt（轮询脚本/agent 10 秒内读取，用后即删）。make auth-input-code CODE=xxxxxx
    auth_local_login.sh 【本地电脑】有头浏览器手动登录 → 检测登录态 → 调 profile_pack.sh 打包（Cookie SOP 路径 A）
    profile_pack.sh 打包 user-data-dir 为 tar.gz（排除锁文件与缓存，校验含 Cookies），输出 scp 上传指引
    auth_vnc.sh 【服务器】Xvfb + noVNC + 有头 Chromium 临时开放（一次性令牌），任意设备浏览器完成登录（Cookie SOP 路径 B）

    与旧路径的映射（spec.md 等历史文档对照）¶

    .trae/specs/live-monitor-agent/spec.md 是设计期快照，路径为当时平铺写法，对照表：

    spec 中的旧路径 现路径
    scripts/monitor/captcha_solver.py scripts/monitor/login/captcha_solver.py
    scripts/monitor/verify_auth.py scripts/monitor/login/verify_auth.py
    scripts/monitor/runtime_state.py scripts/monitor/core/runtime_state.py

    （preflight.sh / force_cleanup.sh / deploy.sh / auth_*.sh 位置不变；monitor_poll.py 为上线后新增，spec 无对应；launcher.py / watchdog.py 的常驻 agent 实现已于 2026-11-09 删除，spec 的 FR-2/FR-7 由此前版本承载，见 git 历史。）

    验证入口¶

make preflight                   # 预检六项
make status                      # 运行状态（读 core/runtime_state）
